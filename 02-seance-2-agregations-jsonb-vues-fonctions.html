CREATE TABLE ventes (
    id             INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    jeu_id         INTEGER      NOT NULL REFERENCES jeux(id),
    plateforme     VARCHAR(10)  NOT NULL,
    mois           DATE         NOT NULL,            -- 1er jour du mois

INSERT INTO ventes (jeu_id, plateforme, mois, quantite, prix_unitaire)
SELECT j.id, p.plateforme, m.mois::DATE,
       100 + (('x' || substr(md5(j.id || p.plateforme || to_char(m.mois, 'YYYY-MM')), 1, 6))::bit(24)::int % 400),
       (j.details ->> 'prix')::NUMERIC
FROM jeux j
CROSS JOIN LATERAL jsonb_array_elements_text(j.details -> 'plateformes') AS p(plateforme)

ORDER BY j.id, p.plateforme, m.mois;

🎛️N10  Agrégats conditionnels : FILTER
Agrégations

🎯 À quoi ça sert

Calculer plusieurs agrégats différents dans une même requête, chacun sur un sous-ensemble de lignes : ventes PC, ventes PS5 et ventes totales côte à côte. C'est ainsi qu'on construit un tableau croisé en une seule lecture de la table.

💡 Analogie — un caissier qui tient plusieurs compteurs en même temps : un pour les paiements par carte, un pour les espèces, un pour le total. Un seul passage en caisse, trois totaux.

🧩 Syntaxe

SQL
AGREGAT(colonne) FILTER (WHERE condition)

-- Équivalent plus ancien, encore très répandu :
SUM(CASE WHEN condition THEN colonne ELSE 0 END)

🔬 Exemple commenté

Ventes de chaque jeu, réparties par plateforme, avec le total :

SQL
SELECT j.titre,
       SUM(v.quantite) FILTER (WHERE v.plateforme = 'PC')     AS pc,
       SUM(v.quantite) FILTER (WHERE v.plateforme = 'PS5')    AS ps5,
       SUM(v.quantite) FILTER (WHERE v.plateforme = 'Switch') AS switch,
       SUM(v.quantite)                                        AS total
FROM ventes v
JOIN jeux j ON j.id = v.jeu_id
GROUP BY j.titre
ORDER BY total DESC;

⚠️ Piège fréquent

Confondre FILTER et WHERE. Le WHERE retire des lignes pour tous les agrégats de la requête ; FILTER ne concerne que l'agrégat auquel il est attaché. Si vous ajoutez WHERE plateforme = 'PC' à la requête ci-dessus, les colonnes PS5, Switch et total ne compteront plus que… le PC.
🧮N11  Sous-totaux : ROLLUP et GROUPING SETS
Agrégations

🎯 À quoi ça sert

Obtenir le détail, les sous-totaux et le total général dans un seul résultat, comme dans un rapport financier. Sans ces outils, il faudrait écrire plusieurs requêtes et les assembler avec UNION ALL.

💡 Analogie — un ticket de caisse détaillé : chaque article, puis un sous-total par rayon, puis le total à payer en bas.

🧩 Syntaxe

SQL
GROUP BY ROLLUP (a, b)            -- (a, b), puis (a), puis () : détail → sous-totaux → total
GROUP BY CUBE (a, b)              -- toutes les combinaisons : (a, b), (a), (b), ()
GROUP BY GROUPING SETS ((a), (b), ())   -- exactement les regroupements listés

GROUPING(colonne)                 -- 1 si la ligne est un sous-total sur cette colonne

🔬 Exemple commenté

Ventes par plateforme et par trimestre, avec sous-totaux par plateforme et total général :

SQL
SELECT CASE WHEN GROUPING(plateforme) = 1 THEN 'TOTAL' ELSE plateforme END AS plateforme,
       CASE WHEN GROUPING(trimestre)  = 1 THEN 'Tous'  ELSE trimestre  END AS trimestre,
       SUM(quantite) AS ventes
FROM (
    SELECT plateforme, 'T' || EXTRACT(QUARTER FROM mois) AS trimestre, quantite
    FROM ventes
) v
GROUP BY ROLLUP (plateforme, trimestre)
ORDER BY GROUPING(plateforme), plateforme, GROUPING(trimestre), trimestre;

Avec GROUPING SETS, on choisit précisément les regroupements voulus : ici un total par plateforme et un total par trimestre, sans le détail croisé.

SQL
SELECT plateforme, trimestre, SUM(quantite) AS ventes
FROM (
    SELECT plateforme, 'T' || EXTRACT(QUARTER FROM mois) AS trimestre, quantite
    FROM ventes
) v
GROUP BY GROUPING SETS ((plateforme), (trimestre))
ORDER BY plateforme, trimestre;

⚠️ Piège fréquent

Sur une ligne de sous-total, la colonne regroupée vaut NULL. Si vos données contiennent de vrais NULL, les deux se confondent. Utilisez GROUPING(colonne), et non colonne IS NULL, pour reconnaître une ligne de sous-total.
🔁N12  LATERAL : une sous-requête pour chaque ligne
LATERAL

🎯 À quoi ça sert

Une sous-requête placée dans le FROM ne peut normalement pas voir les autres tables de la requête. Avec LATERAL, elle est exécutée pour chaque ligne de la table de gauche et peut utiliser ses colonnes. C'est l'outil idéal pour « les N meilleurs éléments de chaque groupe ».

💡 Analogie — un serveur qui passe à chaque table du restaurant : pour chacune, il regarde qui est assis là et propose les desserts adaptés. La sous-requête LATERAL est cette tournée, table par table.

🧩 Syntaxe

SQL
SELECT ...
FROM table_a a
CROSS JOIN LATERAL (
    SELECT ... FROM table_b b
    WHERE b.a_id = a.id          -- utilise une colonne de la table de gauche
    ORDER BY ... LIMIT n
) sous_requete;

-- Pour garder les lignes de gauche sans résultat :
LEFT JOIN LATERAL ( ... ) sous_requete ON true

🔬 Exemple commenté

Le meilleur mois de ventes de chaque jeu :

SQL
SELECT j.titre, TO_CHAR(m.mois, 'YYYY-MM') AS meilleur_mois, m.ventes
FROM jeux j
CROSS JOIN LATERAL (
    SELECT v.mois, SUM(v.quantite) AS ventes
    FROM ventes v
    WHERE v.jeu_id = j.id               -- la sous-requête voit le jeu courant
    GROUP BY v.mois
    ORDER BY ventes DESC
    LIMIT 1
) m
ORDER BY m.ventes DESC;

📌 LATERAL ou fonction de fenêtrage (N8) ? Pour un top N par groupe, les deux fonctionnent. LATERAL est souvent plus efficace quand il y a peu de groupes et un index adapté (séance 3) ; le fenêtrage est plus simple quand on veut aussi le rang.

Sans le mot-clé LATERAL, la sous-requête ne voit pas la table de gauche :

🧬N13  JSONB : des données semi-structurées
JSONB

🎯 À quoi ça sert

Certaines informations n'ont pas la même forme d'une ligne à l'autre : un jeu a un DLC, un autre non ; l'un sort sur 3 plateformes, l'autre sur une seule. Plutôt que de multiplier les colonnes vides, PostgreSQL stocke ces données dans une colonne JSONB : du JSON au format binaire, que l'on peut interroger, filtrer et indexer.

💡 Analogie — une fiche produit avec une partie fixe (le titre, imprimé) et une zone « caractéristiques » libre, où chaque produit liste ce qui le concerne.

🧩 Syntaxe

OpérateurRenvoieExemple
->Un élément JSON (pour continuer à naviguer)details -> 'dlc'
->>Un élément sous forme de textedetails ->> 'editeur'
#>>Un élément imbriqué, en texte, par son chemindetails #>> '{dlc,nom}'
@>Vrai si le JSON contient le fragmentdetails @> '{"multijoueur": true}'
?Vrai si la clé existedetails ? 'dlc'
jsonb_array_elements_text()Une ligne par élément d'un tableau(details -> 'plateformes')

       details #>> '{dlc,nom}'            AS dlc            -- chemin imbriqué
FROM jeux
ORDER BY pegi DESC, titre;

🪟N14  Les vues : une requête enregistrée
Vues

🎯 À quoi ça sert

Une vue est une requête à laquelle on donne un nom. On l'interroge ensuite comme une table, sans réécrire les jointures. Elle sert aussi de contrat entre la base et les applications : on peut réorganiser les tables en interne sans casser le code qui lit la vue, et n'exposer que les colonnes autorisées.

💡 Analogie — une vitrine de magasin : on y présente une sélection mise en forme du stock, sans montrer la réserve. La vitrine ne stocke rien : elle montre ce qui est en rayon à cet instant.

🧩 Syntaxe

SQL
CREATE [OR REPLACE] VIEW nom_vue AS
SELECT ...;

SELECT * FROM nom_vue WHERE ...;          -- s'utilise comme une table

CREATE VIEW nom_vue AS
SELECT ... FROM une_table WHERE condition
WITH CHECK OPTION;                        -- refuse les écritures hors du périmètre de la vue

🔬 Exemple commenté

Une fiche joueur prête à l'emploi, qui masque la jointure :

SQL
CREATE VIEW v_fiche_joueur AS
SELECT j.id, j.nom, j.poste, j.buts,
       e.nom   AS equipe,
       e.ville
FROM joueurs j
LEFT JOIN equipes e ON e.id = j.equipe_id;
SQL
SELECT nom, poste, buts, ville
FROM v_fiche_joueur
WHERE equipe = 'RC Lens';

Une vue simple (une seule table, pas d'agrégat) est modifiable : les écritures sont transmises à la table. WITH CHECK OPTION empêche d'écrire une ligne qui sortirait de la vue :

SQL
CREATE VIEW v_attaquants AS
SELECT id, nom, poste, buts, equipe_id
FROM joueurs
WHERE poste = 'attaquant'
WITH CHECK OPTION;
SQL
INSERT INTO v_attaquants (nom, poste, buts, equipe_id)
VALUES ('Léo Blanc', 'défenseur', 0, 3);
✖ Erreur PostgreSQL
ERROR:  new row violates check option for view "v_attaquants"
DETAIL:  Failing row contains (12, Léo Blanc, 3, défenseur, 0).

⚠️ Piège fréquent

Une vue ne stocke pas de données : sa requête est réexécutée à chaque lecture. Une vue lente reste lente, et empiler des vues qui appellent d'autres vues cache des requêtes énormes. Autre piège : SELECT * dans une vue fige la liste des colonnes au moment de sa création ; une colonne ajoutée ensuite à la table n'y apparaît pas.
📸N15  Les vues matérialisées : un résultat mis en cache
Vues

🎯 À quoi ça sert

Une vue matérialisée exécute sa requête une fois et stocke le résultat, comme une table. La lecture devient instantanée, même si la requête est coûteuse. En contrepartie, le résultat n'est à jour qu'après un REFRESH. On l'utilise pour les tableaux de bord, classements et statistiques qui n'ont pas besoin d'être à la seconde près.

💡 Analogie — une photo du tableau des scores : on la consulte instantanément, mais elle ne change pas tant qu'on n'en reprend pas une nouvelle.

🧩 Syntaxe

SQL
CREATE MATERIALIZED VIEW nom AS
SELECT ...;

REFRESH MATERIALIZED VIEW nom;                 -- recalcule (bloque les lectures pendant le calcul)

CREATE UNIQUE INDEX ON nom (colonne);          -- prérequis pour CONCURRENTLY
REFRESH MATERIALIZED VIEW CONCURRENTLY nom;    -- recalcule sans bloquer les lectures

🔬 Exemple commenté

Le classement du championnat (requête vue en N6), calculé une fois pour toutes :

SQL
CREATE MATERIALIZED VIEW mv_classement AS
WITH resultats AS (
    SELECT equipe_dom_id AS equipe_id, buts_dom AS pour, buts_ext AS contre FROM matchs
    UNION ALL
    SELECT equipe_ext_id, buts_ext, buts_dom FROM matchs
)
SELECT e.nom AS equipe,
       SUM(CASE WHEN r.pour > r.contre THEN 3 WHEN r.pour = r.contre THEN 1 ELSE 0 END) AS points,
       SUM(r.pour - r.contre) AS difference
FROM resultats r
JOIN equipes e ON e.id = r.equipe_id
GROUP BY e.nom;
SQL
SELECT * FROM mv_classement ORDER BY points DESC, difference DESC;

REFRESH MATERIALIZED VIEW CONCURRENTLY mv_classement;

⚠️ Piège fréquent

Oublier que les données sont figées : une vue matérialisée jamais rafraîchie affiche des chiffres faux sans aucun message d'erreur. Il faut décider qui la rafraîchit et quand (tâche planifiée, après un import…). Et CONCURRENTLY exige un index unique :
SQL
DROP INDEX mv_classement_equipe_idx;
REFRESH MATERIALIZED VIEW CONCURRENTLY mv_classement;
✖ Erreur PostgreSQL
ERROR:  cannot refresh materialized view "public.mv_classement" concurrently
HINT:  Create a unique index with no WHERE clause on one or more columns of the materialized view.
SQL
CREATE UNIQUE INDEX ON mv_classement (equipe);
🧰N16  Fonctions SQL : réutiliser un calcul
Fonctions

🎯 À quoi ça sert

Une fonction enregistre un calcul paramétré dans la base : on l'appelle avec des arguments, où que l'on soit (requêtes, vues, autres fonctions). Une fonction en LANGUAGE sql contient simplement une ou plusieurs requêtes SQL. Elle peut renvoyer une valeur, ou une table entière avec RETURNS TABLE.

💡 Analogie — une recette enregistrée dans un robot de cuisine : on choisit les ingrédients (les paramètres), on appuie sur un bouton, le robot applique toujours la même recette.

🧩 Syntaxe

SQL
CREATE [OR REPLACE] FUNCTION nom(param1 TYPE, param2 TYPE)
RETURNS type_retour                -- ou RETURNS TABLE (col1 TYPE, col2 TYPE)
LANGUAGE sql
IMMUTABLE | STABLE | VOLATILE      -- voir N17
AS $$
    SELECT ...;                    -- le corps, entre $$ … $$
$$;

SELECT nom(valeur1, valeur2);      -- appel d'une fonction scalaire
SELECT * FROM nom(valeur);         -- appel d'une fonction qui renvoie une table

🔬 Exemple commenté

Une fonction qui calcule les points d'un match, utilisable dans n'importe quelle requête :

SQL
CREATE FUNCTION points(pour INTEGER, contre INTEGER)
RETURNS INTEGER
LANGUAGE sql
IMMUTABLE                          -- même entrée = même résultat, sans lire de table
AS $$
    SELECT CASE WHEN pour > contre THEN 3
                WHEN pour = contre THEN 1
                ELSE 0 END;
$$;
SQL
SELECT journee, buts_dom, buts_ext,
       points(buts_dom, buts_ext) AS pts_domicile,
       points(buts_ext, buts_dom) AS pts_exterieur
FROM matchs
WHERE journee = 1;

Une fonction qui renvoie une table : tous les matchs d'une équipe, vus de son côté.

SQL
CREATE FUNCTION matchs_equipe(p_equipe TEXT)
RETURNS TABLE (journee INTEGER, adversaire VARCHAR, score TEXT, pts INTEGER)
LANGUAGE sql
STABLE                             -- lit des tables : jamais IMMUTABLE
AS $$
    SELECT m.journee, adv.nom,
           CASE WHEN e.id = m.equipe_dom_id THEN m.buts_dom || '-' || m.buts_ext
                ELSE m.buts_ext || '-' || m.buts_dom END,
           CASE WHEN e.id = m.equipe_dom_id THEN points(m.buts_dom, m.buts_ext)
                ELSE points(m.buts_ext, m.buts_dom) END
    FROM matchs m
    JOIN equipes e   ON e.id IN (m.equipe_dom_id, m.equipe_ext_id)
    JOIN equipes adv ON adv.id IN (m.equipe_dom_id, m.equipe_ext_id) AND adv.id <> e.id
    WHERE e.nom = p_equipe
    ORDER BY m.journee;
$$;

⚠️ Piège fréquent

CREATE OR REPLACE remplace le corps d'une fonction, mais pas son type de retour :
SQL
CREATE OR REPLACE FUNCTION points(pour INTEGER, contre INTEGER)
RETURNS NUMERIC
LANGUAGE sql IMMUTABLE
AS $$ SELECT 3.0; $$;
✖ Erreur PostgreSQL
ERROR:  cannot change return type of existing function
HINT:  Use DROP FUNCTION points(integer,integer) first.
Il faut d'abord supprimer la fonction avec sa signature complète : DROP FUNCTION points(INTEGER, INTEGER);. La signature compte, car PostgreSQL autorise plusieurs fonctions de même nom avec des paramètres différents.
⚙️N17  Fonctions PL/pgSQL : de la logique dans la base
Fonctions

🎯 À quoi ça sert

Quand une requête ne suffit plus (variables, conditions, boucles, messages d'erreur métier), on écrit la fonction en PL/pgSQL, le langage procédural de PostgreSQL. Il ajoute au SQL les structures d'un langage de programmation classique.

💡 Analogie — la fonction SQL est une recette en une étape ; la fonction PL/pgSQL est un chef qui goûte, ajuste et refuse d'envoyer un plat raté (RAISE EXCEPTION).

🧩 Syntaxe

SQL
CREATE OR REPLACE FUNCTION nom(p_param TYPE)
RETURNS type_retour
LANGUAGE plpgsql
STABLE
AS $$
DECLARE
    v_variable TYPE := valeur_initiale;   -- variables locales
BEGIN
    SELECT ... INTO v_variable FROM ...;  -- stocker un résultat
    IF NOT FOUND THEN                     -- aucune ligne trouvée
        RAISE EXCEPTION 'Message : %', p_param;
    END IF;
    FOR r IN SELECT ... LOOP              -- parcourir un résultat
        ...
    END LOOP;
    RETURN v_variable;
END;
$$;
VolatilitéPromesse faite à PostgreSQLExemple
IMMUTABLEMêmes arguments = même résultat, pour toujours. Ne lit aucune table.points(3, 1)
STABLEMême résultat pendant une requête. Peut lire des tables.matchs_equipe('PSG')
VOLATILEAucune promesse (valeur par défaut). Peut écrire.random(), une insertion

🔬 Exemple commenté

La forme d'une équipe sur ses derniers matchs, au format « V N D » :

SQL
CREATE FUNCTION forme(p_equipe TEXT, p_nb INTEGER DEFAULT 3)
RETURNS TEXT
LANGUAGE plpgsql
STABLE
AS $$
DECLARE
    v_id     INTEGER;
    v_forme  TEXT := '';
    r        RECORD;
BEGIN
    -- 1. Vérifier que l'équipe existe
    SELECT id INTO v_id FROM equipes WHERE nom = p_equipe;
    IF NOT FOUND THEN
        RAISE EXCEPTION 'Équipe inconnue : %', p_equipe;
    END IF;

    -- 2. Parcourir ses derniers matchs, du plus récent au plus ancien
    FOR r IN
        SELECT pts FROM matchs_equipe(p_equipe) ORDER BY journee DESC LIMIT p_nb
    LOOP
        v_forme := v_forme || CASE r.pts WHEN 3 THEN 'V' WHEN 1 THEN 'N' ELSE 'D' END;
    END LOOP;

    RETURN v_forme;
END;
$$;
SQL
SELECT nom, forme(nom) AS trois_derniers, forme(nom, 5) AS cinq_derniers
FROM equipes
ORDER BY nom;

⚠️ Piège fréquent

Déclarer IMMUTABLE une fonction qui lit une table. PostgreSQL vous croit sur parole : il peut mettre le résultat en cache ou l'utiliser dans un index, et renvoyer une valeur périmée après une modification des données. Aucun message ne vous prévient. En cas de doute : STABLE pour une fonction qui lit, VOLATILE pour une fonction qui écrit.
