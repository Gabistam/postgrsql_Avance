🧠Étape 1  Comprendre ce qu'on installe

PostgreSQL fonctionne en deux parties, comme un restaurant :

🍽️ Le serveur PostgreSQL, c'est la cuisine : il stocke les données et exécute les requêtes, en arrière-plan, en permanence.
🧑‍💼 Le client (psql ou DBeaver), c'est le serveur en salle : il prend votre commande (la requête SQL), l'apporte en cuisine et vous rapporte le plat (le résultat).
ÉlémentRôleObligatoire ?
Serveur PostgreSQLStocke les bases et exécute le SQLOui
psqlClient en ligne de commande, installé avec le serveurOui
pgAdmin ou DBeaverClient graphique : éditeur SQL, résultats en tableauConseillé (au choix)
📌 Version attendue : PostgreSQL 16 ou 17. Une version plus ancienne fonctionnera pour la plupart des notions, mais pas toutes.
⬇️Étape 2  Installer PostgreSQL

Choisissez votre système :

  1. Allez sur postgresql.org → Download → Windows et téléchargez l'installeur (proposé par EDB), version 17.
  2. Lancez l'installeur. Laissez cochés PostgreSQL Server, pgAdmin 4 et Command Line Tools. Stack Builder est inutile.
  3. Choisissez le mot de passe du superutilisateur postgres et notez-le.
  4. Laissez le port par défaut 5432 et la locale par défaut, puis terminez l'installation.
  5. Pour utiliser psql dans n'importe quel terminal, ajoutez ce dossier à la variable d'environnement Path (Paramètres → « Modifier les variables d'environnement système ») :
Dossier à ajouter au Path
C:\Program Files\PostgreSQL\17\bin
💡 Alternative sans toucher au Path : dans le menu Démarrer, ouvrez SQL Shell (psql). Il vous pose 5 questions : appuyez sur Entrée pour garder les valeurs par défaut, puis tapez votre mot de passe.

Option A — Postgres.app (la plus simple)

  1. Téléchargez Postgres.app sur postgresapp.com et glissez-la dans Applications.
  2. Ouvrez-la et cliquez sur Initialize : le serveur démarre.
  3. Rendez psql disponible dans le Terminal :
Terminal
sudo mkdir -p /etc/paths.d &&
echo /Applications/Postgres.app/Contents/Versions/latest/bin | sudo tee /etc/paths.d/postgresapp

Fermez puis rouvrez le Terminal.

Option B — Homebrew

Terminal
brew install postgresql@17
brew services start postgresql@17
echo 'export PATH="/opt/homebrew/opt/postgresql@17/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
⚠️ Sur Mac, l'utilisateur par défaut est votre nom d'utilisateur macOS, sans mot de passe. Dans la suite, remplacez -U postgres par votre nom, ou retirez simplement -U postgres.
Ubuntu / Debian
sudo apt update
sudo apt install postgresql
sudo systemctl status postgresql     # doit afficher « active »

Sous Linux, on se connecte avec le compte système postgres. Pour pouvoir aussi se connecter avec un mot de passe (utile pour DBeaver), définissez-en un :

Terminal
sudo -u postgres psql
\password postgres
\q

Si Docker Desktop est déjà installé, une seule commande suffit :

Terminal
docker run --name pg-cours -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgres:17

Le mot de passe est postgres. Pour ouvrir psql dans le conteneur :

Terminal
docker exec -it pg-cours psql -U postgres
💡 Le conteneur s'arrête quand vous éteignez Docker. Relancez-le avec docker start pg-cours.
🔎Étape 3  Vérifier l'installation

Ouvrez un terminal (Invite de commandes ou PowerShell sous Windows) et tapez :

Terminal
psql --version

Vous devez obtenir une ligne du type psql (PostgreSQL) 17.x. Si le terminal répond que la commande est introuvable, voir Dépannage → « psql n'est pas reconnu ».

🔌Étape 4  Se connecter avec psql

Connectez-vous au serveur avec le compte postgres :

Terminal
psql -U postgres -h localhost
Terminal
psql
Terminal
sudo -u postgres psql

Tapez votre mot de passe (rien ne s'affiche pendant la saisie, c'est normal). Vous arrivez sur l'invite :

Invite psql
postgres=#

Testez votre première requête. Notez le point-virgule final : c'est lui qui déclenche l'exécution.

SQL
SELECT version();

Pour quitter psql : \q

💡 Si l'invite devient postgres-# au lieu de postgres=#, psql attend la suite de votre requête : vous avez oublié le ;. Tapez-le puis Entrée.

📌 Le choix n'a aucune incidence sur le cours : les requêtes sont les mêmes. Installez celui qui vous convient ; vous pourrez toujours changer.
  1. Windows : pgAdmin 4 a été installé avec PostgreSQL (étape 2) ; ouvrez-le depuis le menu Démarrer. Mac / Linux : téléchargez-le sur pgadmin.org et installez-le.
  2. Au premier lancement, pgAdmin demande de définir un mot de passe maître. Il protège les mots de passe de connexion que pgAdmin mémorisera. Notez-le aussi.
  3. Dans le panneau de gauche, dépliez Servers. Sous Windows, votre serveur local (« PostgreSQL 17 ») est déjà enregistré : cliquez dessus et saisissez le mot de passe de postgres.
  4. S'il n'apparaît pas : clic droit sur Servers → Register → Server…. Onglet General : un nom, par exemple Local. Onglet Connection : Host localhost, Port 5432, Maintenance database postgres, Username postgres, votre mot de passe, puis Save.
  5. Pour écrire du SQL : clic droit sur une base → Query Tool. F5 exécute le script (ou la partie sélectionnée).
💡 En séance 3, les boutons Explain (F7) et Explain Analyze (Maj+F7) du Query Tool affichent les plans d'exécution sous forme de schéma.
  1. Téléchargez DBeaver Community (gratuit) sur dbeaver.io et installez-le.
  2. Cliquez sur Nouvelle connexion (icône de prise électrique) → PostgreSQL.
  3. Renseignez : Host localhost, Port 5432, Database postgres, Username postgres, et votre mot de passe.
  4. Cliquez sur Tester la connexion. À la première utilisation, DBeaver propose de télécharger le pilote : acceptez.
  5. Validez avec Terminer. Pour écrire du SQL : clic droit sur la connexion → Éditeur SQL → Nouveau script. Ctrl+Entrée exécute la requête sous le curseur, Alt+X tout le script.
💡 En séance 3, Ctrl+Maj+E affiche le plan d'exécution de la requête sous le curseur.
🗄️Étape 6  Créer la base de travail

Une fois connecté dans psql (invite postgres=#), créez la base qui servira à tout le cours, puis connectez-vous dessus :

psql
CREATE DATABASE cours_sql;
\c cours_sql

L'invite devient cours_sql=# : vous êtes dans la bonne base.

Ou depuis votre client graphique :

Clic droit sur Databases → Create → Database…, nommez-la cours_sql, puis Save. Ouvrez ensuite le Query Tool sur cette base (clic droit sur cours_sql).

Clic droit sur la connexion → Créer → Base de données, nommez-la cours_sql. Modifiez ensuite la connexion (clic droit → Éditer la connexion) pour que « Database » pointe sur cours_sql.

📥Étape 7  Charger le jeu de démonstration

Le fichier demo.sql crée 6 petites tables sur trois univers : un championnat de foot, des genres musicaux avec des streams, et des scores de jeux vidéo. Tous les exemples du cours s'appuient dessus.

Puis chargez-le, depuis le dossier où se trouve le fichier :

Terminal
psql -U postgres -h localhost -d cours_sql -f demo.sql
psql
\i C:/Users/votre_nom/Downloads/demo.sql

Utilisez des / même sous Windows.

Terminal
cp demo.sql /tmp/demo.sql
sudo -u postgres psql -d cours_sql -f /tmp/demo.sql

La copie dans /tmp évite une erreur de permission : le compte postgres ne peut pas lire votre dossier personnel.

Terminal
docker cp demo.sql pg-cours:/demo.sql
docker exec -it pg-cours psql -U postgres -d cours_sql -f /demo.sql

Dans le Query Tool ouvert sur cours_sql, cliquez sur l'icône Open File (dossier) et choisissez demo.sql, ou collez son contenu. Exécutez tout avec F5, sans rien sélectionner.

Ouvrez un éditeur SQL sur la base cours_sql, collez le contenu du fichier et exécutez tout le script avec Alt+X (et non Ctrl+Entrée, qui n'exécute qu'une requête).

✅ À la première exécution, des messages NOTICE: table … does not exist, skipping s'affichent : c'est normal. Le script supprime les tables avant de les recréer, ce qui permet de le relancer à tout moment pour repartir de zéro.
Voir le contenu de demo.sql
demo.sql
-- =====================================================================
--  Jeu de données de démonstration — SQL avancé avec PostgreSQL
--  Domaines : sport (championnat), musique (genres, streams), jeux vidéo
--  Script ré-exécutable : il supprime puis recrée toutes les tables.
-- =====================================================================

-- (tournois et inscriptions sont créées pendant les exercices N2)
DROP TABLE IF EXISTS inscriptions, tournois, joueurs, matchs, equipes, genres, parties, streams CASCADE;

-- ---------- SPORT : un mini-championnat de 6 équipes ----------
CREATE TABLE equipes (
    id    INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nom   VARCHAR(50) NOT NULL UNIQUE,
    ville VARCHAR(50) NOT NULL
);

CREATE TABLE joueurs (
    id        INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nom       VARCHAR(80) NOT NULL,
    equipe_id INTEGER REFERENCES equipes(id),      -- NULL = joueur sans club
    poste     VARCHAR(20) NOT NULL,
    buts      INTEGER NOT NULL DEFAULT 0 CHECK (buts >= 0)
);

CREATE TABLE matchs (
    id             INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    journee        INTEGER NOT NULL,
    equipe_dom_id  INTEGER NOT NULL REFERENCES equipes(id),
    equipe_ext_id  INTEGER NOT NULL REFERENCES equipes(id),
    buts_dom       INTEGER NOT NULL CHECK (buts_dom >= 0),
    buts_ext       INTEGER NOT NULL CHECK (buts_ext >= 0)
);

🛟Erreurs fréquentes et solutions
« psql n'est pas reconnu » / « command not found »

Le dossier de PostgreSQL n'est pas dans le Path. Sous Windows, ajoutez C:\Program Files\PostgreSQL\17\bin au Path puis rouvrez le terminal, ou utilisez SQL Shell (psql). Sous Mac, refaites la commande de l'étape 2 puis rouvrez le Terminal.

« password authentication failed for user postgres »

Mot de passe incorrect. Sous Windows, c'est celui choisi pendant l'installation. Sous Linux, définissez-le avec \password postgres (étape 2). Sous Mac, l'utilisateur est votre nom macOS, sans mot de passe.

« connection refused » / « could not connect to server »

Le serveur n'est pas démarré. Windows : services → postgresql-x64-17 → Démarrer. Mac : ouvrez Postgres.app ou brew services start postgresql@17. Linux : sudo systemctl start postgresql. Docker : docker start pg-cours.

« port 5432 is already in use »

Un autre PostgreSQL tourne déjà (ancienne installation, autre conteneur). Arrêtez-le, ou lancez Docker sur un autre port : -p 5433:5432, puis connectez-vous avec -p 5433.

« Console code page (850) differs from Windows code page (1252) »

Simple avertissement sous Windows : les accents peuvent mal s'afficher. Tapez chcp 1252 avant de lancer psql, ou utilisez DBeaver.

« demo.sql: No such file or directory »

Vous n'êtes pas dans le dossier du fichier. Placez-vous dedans avec cd, ou indiquez le chemin complet du fichier.

« Permission denied » en chargeant demo.sql sous Linux

Le compte postgres ne peut pas lire votre dossier personnel. Copiez le fichier dans /tmp (voir étape 7).

pgAdmin demande un « master password » que j'ai oublié

Ce mot de passe ne sert qu'à pgAdmin, pas à PostgreSQL. Sur l'écran de saisie, choisissez Reset Master Password : pgAdmin oublie les mots de passe enregistrés, qu'il suffira de ressaisir à la prochaine connexion.

Rien ne se passe avec F5 (pgAdmin) ou Alt+X (DBeaver)

Vérifiez que l'éditeur est bien ouvert sur la base cours_sql (nom affiché dans l'onglet ou la barre de l'éditeur) et que la connexion est active. Dans pgAdmin, une sélection partielle n'exécute que le texte sélectionné.

L'invite affiche postgres-# et rien ne se passe

psql attend la fin de la requête : ajoutez ; et Entrée. Pour tout annuler : Ctrl+C.
