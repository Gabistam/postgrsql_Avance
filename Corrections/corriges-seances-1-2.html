#AffirmationRéponseExplication
1Une méta-commande psql comme \dt doit se terminer par un point-virgule.FauxLes méta-commandes n'en prennent pas ; seules les requêtes SQL se terminent par ;.
2NUMERIC est le type adapté pour stocker des montants en euros.VraiNUMERIC est exact ; FLOAT et REAL sont approximatifs et créent des erreurs d'arrondi.
3WHERE equipe_id = NULL trouve les joueurs sans club.FauxUne comparaison avec NULL n'est jamais vraie : il faut écrire IS NULL.
4Dans une condition, AND est évalué avant OR.VraiC'est pourquoi il faut des parenthèses dès qu'on mélange AND et OR.
5Un INNER JOIN conserve toutes les lignes de la table de gauche.FauxC'est le rôle du LEFT JOIN. L'INNER JOIN supprime les lignes sans correspondance.
6HAVING filtre les groupes, après le GROUP BY.VraiWHERE filtre les lignes avant le regroupement, HAVING filtre les groupes après.
7On peut utiliser dans le WHERE un alias défini dans le SELECT.FauxLe WHERE est évalué avant le SELECT : l'alias n'existe pas encore.
8Une CTE reste disponible pour les requêtes suivantes de la session.FauxUne CTE n'existe que le temps de la requête qui la suit.
9Plusieurs CTE s'enchaînent avec un seul WITH, séparées par des virgules.VraiOn n'écrit WITH qu'une fois ; chaque CTE peut utiliser les précédentes.
10Une CTE récursive combine un ancrage et une étape récursive avec UNION ALL (ou UNION).VraiL'ancrage donne le point de départ, l'étape récursive le niveau suivant.
11Remplacer UNION ALL par UNION dans une CTE récursive peut empêcher une boucle infinie.VraiUNION supprime les lignes déjà trouvées : sur un graphe avec des cycles, la récursion finit par ne plus rien produire de neuf.

15On peut filtrer directement sur ROW_NUMBER() dans le WHERE.FauxLes fonctions de fenêtrage sont calculées après le WHERE : on filtre dans une requête englobante ou une CTE.
16LAG renvoie NULL pour la première ligne de chaque partition.VraiIl n'y a pas de ligne précédente (sauf si on fournit une valeur par défaut en 3e argument).

#AffirmationRéponseExplication
1FILTER ne s'applique qu'à l'agrégat auquel il est attaché, contrairement à WHERE.VraiWHERE retire des lignes pour tous les agrégats ; FILTER n'agit que sur le sien.
2SUM(x) FILTER (WHERE …) peut renvoyer NULL.VraiSi aucune ligne ne passe le filtre, la somme porte sur un ensemble vide et vaut NULL.

4Sur une ligne de sous-total, la colonne regroupée vaut NULL.VraiC'est pourquoi on utilise GROUPING() pour distinguer un sous-total d'un vrai NULL.
5GROUPING(colonne) vaut 1 sur une ligne de sous-total de cette colonne.VraiEt 0 sur une ligne de détail.
6Une sous-requête du FROM peut toujours utiliser les colonnes des tables placées avant elle.FauxIl faut le mot-clé LATERAL ; sinon, PostgreSQL renvoie une erreur de référence invalide.

Écrivez une fonction SQL compatibilite(pseudo_a, pseudo_b) qui renvoie les films notés par les deux membres, avec les deux notes et leur écart. Utilisez-la ensuite pour calculer, en une requête, le nombre de films communs et l'écart moyen entre cinephile_92 et nolanfan.

✅ Correction

SQL
CREATE OR REPLACE FUNCTION compatibilite(p_a TEXT, p_b TEXT)
RETURNS TABLE (titre VARCHAR, note_a NUMERIC, note_b NUMERIC, ecart NUMERIC)
LANGUAGE sql
STABLE
AS $$
    SELECT f.titre, na.note, nb.note, ABS(na.note - nb.note)
    FROM notes na
    JOIN utilisateurs ua ON ua.id = na.utilisateur_id AND ua.pseudo = p_a
    JOIN notes nb        ON nb.film_id = na.film_id
    JOIN utilisateurs ub ON ub.id = nb.utilisateur_id AND ub.pseudo = p_b
    JOIN films f         ON f.id = na.film_id
    ORDER BY ABS(na.note - nb.note) DESC, f.titre;
$$;
